01项目概述

日常最有价值的画面往往来不及记：一段报错、一页文档、一张数据表、一个配置项。截图容易，但截图之后散落在相册里就再也找不回来了。月忆解决的是「捕获之后的整理与回忆」——按下快捷键，剩下的全自动。

形态上是 Tauri 2 桌面应用（Rust 外壳 + WebView2 前端），技术选择上坚持 Local First：数据库、截图、附件全部存在本地；只有用户主动触发 AI 时，相关片段才会发给模型，绝不默认上传整个记忆库。

一键捕获闭环
Alt+Shift+S 全屏截图 → 立即入库（不阻塞）→ 后台 OCR → AI 整理 → 系统通知
离线 OCR 不联网
直接调 Windows WinRT OcrEngine，中英混排界面实测识别 353 字，无需第三方 OCR 服务
AI 结构化理解
一次捕获拆成标题 / 摘要 / 标签 / 分类四项，单项失败不影响其余，异常 JSON 容错解析
Ctrl+K 检索问答
命令面板兼全局搜索，问答只带 8 条相关记忆摘要，回答里的 [1] 可点回原始截图
系统级集成
全局快捷键、系统托盘、自定义 memex-img 协议、DPI 感知截图、DWM 圆角小窗
自带设计系统
Token 单一来源、13 种基元组件、应用内 UI 实验室、非标准字号审计、像素级视觉回归

三层职责边界很清晰：前端只管呈现与交互（React + Zustand），Rust 核心管能力（截图、OCR、文件、调度），数据与模型都在进程外（SQLite 文件 + DeepSeek API）。AI 调用被抽象成 AiProvider trait，换供应商只需实现一个 trait。

04核心闭环：一次捕获发生了什么

① 捕获 — Alt+Shift+S 触发 GDI 全屏位图（含分层窗口），编码 PNG 写入 MemexData/screenshots/，同时插入 memories 记录，状态标为「待整理」，UI 立刻提示「已捕获」
② 识别 — 后台线程调 WinRT OCR 提取文字；语言包缺失或识别失败时原图照常保留，只记录降级原因，不影响后续手动整理
③ 理解 — 把 OCR 文本交给 DeepSeek 做四件事：起标题、写摘要、打标签、归分类。四项分别调用，任一项失败其余继续，不会整体回滚
④ 归档 — 回写 memories / tags / memory_tags / collections，ai_status 置为 done，发系统通知；时间线上出现带「新捕获」标记的卡片
⑤ 回忆 — 任意时刻 Ctrl+K 打开命令面板，走关键词搜索或 AI 问答；问答上下文只给 8 条相关记忆摘要，回答带 [1][2] 引用，点击直接回到原始截图

这条链路上最容易出事的是 ③：模型返回的 JSON 经常带 ```json 包裹、前后废话、字段名漂移。于是写了一个 parse_json_loose——先剥围栏、再截取第一个完整 JSON 片段、最后逐字段兜底，实测未再因格式问题丢数据。

06工程细节：降级与护栏

异常场景实际行为
API Key 未配置 / 错误AI 标记失败，记忆完整保存，UI 明确提示「AI 离线」
网络断开本地记录、搜索、截图、合集全部可用
OCR 失败（缺语言包）保留原图，ocr_text 留空并写日志，不阻塞入库
模型返回异常 JSONparse_json_loose 三段容错：剥围栏 → 截取 JSON → 字段兜底
AI 单项失败（如标签）其余项继续写入，不整体回滚
数据库错误命令返回 Result，前端 toast 提示，进程不崩
截图失败托盘与快捷键路径 emit capture-error，前端提示原因

设计系统同样有护栏：所有颜色/字号/间距只允许来自 src/ui/tokens.css，npm run audit:ui 会扫描页面里的裸色值与非标准字号（--strict 可在 CI 中失败）；再加一个 ui-diff.py 做像素级回归，改完 UI 能一眼看出哪里动了。
